## 오늘 배운 내용

#### 📌 에이전트 주도 개발 방법에 대한 고민

본격적으로 기능 구현에 들어갔는데 속도가 안 난다. 내가 스펙을 너무 과하게 작성하려고 하는 문제도 있고, 코드 리뷰 절차에 대해 생각하지 않고 너무 에이전트에게 위임해버려서 리뷰 핑퐁이 너무 오래 지속된 것도 문제였다. 코드 핑퐁은 P0, P1에 대해서만 반영하고 나머지는 백로그로 옮기거나 추후 반영하는 방식으로 진행하기로 결정했다. 완전히 에이전트에게 맡긴 상태로 0부터 무언가를 만들어 본 경험이 없다 보니, 그리고 지금 만들고 있는 기능이 백엔드 단의 기능이다보니 잘 몰라서 그런지 많이 더디게 느껴지는 것 같다. 절충안을 잘 찾아보자.

## 더 알아보고 싶은 것

#### ❓ 클로드 코드 팀즈, 오케스트레이션을 사용해서 효율적으로 병렬 개발하기

오케스트레이션에 한번 토큰을 크게 빼앗긴 이후로 잘 건드리고 있지 않긴 한데, 5일이라는 짧은 기간 내에 빠르게 제품을 만들고 검증해보려면 개발을 빠르게 하는 게 가장 중요할 것 같다. 제일 중요한 채팅 UI는 아직 시작도 못 해서 빨리 구현해야 한다. 어떻게 하면 오케스트레이션이나 클로드 코드 팀즈를 써서 여러 기능들을 병렬적으로 빠르게 개발할 수 있을지 고민해봐야 할 것 같다.

## 나에게 적용한다면

#### 💡 기능 정의서는 메인 이슈로, 세부 태스크는 하위 이슈로

기능 정의서를 메인 이슈로 올리고 세부 태스크를 메인 이슈의 서브 이슈로 등록하자. 그리고 메인 이슈를 메인 오케스트레이터, 세부 이슈를 서브 에이전트들이 담당하도록 해보자. 이렇게 하면 토큰은 많이 쓸 수 있겠지만 구현 속도를 비약적으로 올릴 수 있을 것 같다. 일단 써 보는 게 중요하니까. 그리고 너무 명세와 스펙에 집착하지 말자. 지금 상황에서 제일 중요한 건 빠르게 결과물을 확인하는 거다.
