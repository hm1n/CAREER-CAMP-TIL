#### 📌 테스트의 중요성

채용 공고에 항상 있으니까, 우대사항이니까, 남들이 다 중요하다고 하니까 테스트 도입해야지 하는 마음으로 시작했지만, 오히려 테스트를 구현하고 CI를 도입하면서 테스트가 얼마나 중요한 지 느낄 수 있었다. 대규모 변경이 있을 때 그 영향 범위를 파악하고 제품에 미치는 영향을 미리 감지할 수 있다는 게 테스트의 가장 큰 역할이고, 앞으로 엔빵에 예정되어 있는 API Route 이관, React Query 도입 등 대규모 변경 전에 이 작업이 선행되어야 서비스 안정성을 유지할 수 있다는 걸 알게 되었다. 매번 시간이 없고 구현이 바쁘다는 걸 핑계로 테스트는 알아 봐야지, 찾아 봐야지 하고 뒤로 미루기만 했었는데 오히려 AI 시대가 도래하면서 딸깍으로 테스트 코드를 작성할 수 있고, 쉽게 자료를 찾아볼 수 있어서 좋은 것 같다.

## 새롭게 알게된 것

#### 🗣 회귀 테스트

회귀 테스트는 코드 수정 후 기존 기능이 여전히 정상적으로 동작하는지 확인하기 위해 진행하는 테스트를 말한다. 새 기능 추가, 버그 수정, 리팩토링 등에서 생기는 의도치 않은 부작용을 조기에 발견하는 것이 목적이다. 단위 테스트, 통합 테스트는 어느 정도 알고 있었고 회귀 테스트도 대충 개념적인 것만 알고 있었지 정확한 뜻은 몰라서 이번 기회에 좀 찾아봤다.

- **`단위 테스트`** **가장 작은 코드 단위 하나**(함수, 클래스, 메서드)를 외부 의존과 격리해 검증하는 테스트
- **`통합 테스트`** DB, 네트워크, 외부 API 등의 경계 내에서 여러 모듈이 맞물려 잘 동작하는지 검증하는 테스트
- **`E2E 테스트`** 사용자 시나리오 전체를 실제 환경에 가깝게 처음부터 끝까지 검증하는 테스트

## 더 알아보고 싶은 것

#### ❓ 단위 테스트, 통합 테스트, E2E 테스트 등 각 테스트가 필요한 지점

각 테스트가 언제 필요하고 어떨 때 사용하는 것인지는 알게 되었지만, 내 프로젝트의 어느 단위에서 어떨 때 도입해야 할 지는 잘 모르겠다. 이건 LLM의 도움을 받아서 충분히 찾아보고 체화할 수 있는 내용인 것 같아서, 추가로 테스트를 구현하면서 더 알아보려고 한다.

#### ❓ 테스트 도입을 통해 얻은 효과를 기록하는 방법

하여튼 예방 차원에서 테스트는 도입했지만, 이게 실제로 어떤 효과가 있고 내 프로젝트에서 테스트로 인해 실제로 어떤 이득을 얻게 되었는지는 기록해둬야 하는 부분인 것 같다. 이것도 잘 찾아보고 기록할 수 있도록 해야겠다.
