# 2026-08-04

## 오늘 배운 내용

#### 📌 프롬프트를 쪼개기

불명확한 프롬프트를 명확하게 만드는 걸 넘어 긴 프롬프트를 작업 단위로 나누고 분리하는 작업을 해봤다. 너무 막막하고 답답하면 프롬프트 뭉땡이를 넘겨버리고 책임을 AI에게 전가해버리곤 했는데, 그런 점을 반성하게 됐다.
프롬프트를 쪼개는 걸 넘어, 오늘 스킬을 배포하면서 Claude의 공식 문서 내용 중 [스킬을 작성하는 Best Practice](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) 에 대해서도 알게 되었다. '최대한 간단하게 작성하기', '복잡한 것들은 references로 나누기' 등의 규칙이 프롬프트를 쪼개는 것과 비슷하다고 느꼈다. 스킬 작성 시에 참고해보면 좋을 것 같다.

#### 📌 스킬 찍어 먹어 보기

기존에는 직접 필요한 스킬을 만들거나, 개발할 때 정말 필수적인 스킬들 *(커밋, PR 등등…)* 에만 스킬을 활용해봤었다. 오늘은 스킬 마켓플레이스도 둘러보고, 다른 팀원들과 불편한 반복 작업에 대해 이야기를 나누면서 어떤 스킬들이 실제로 많이 사용되고 있는지 알아볼 수 있었다. 내가 쓰는 스킬들 말고도 더 다양한 곳에 스킬을 적용하고 자동화할 수 있다는 사실을 알게 되었다.

## 더 알아보고 싶은 것

#### ❓ LLM 위키 적용 사례 찾아보기

기존에 쓰던 ChatGPT, Codex에 더해 Claude Code까지 활용하게 되면서 AI 간의 맥락 공유와 서로가 정한 결정 사항에 대한 기록이 너무 중요해졌다고 느낀다. 그래서 LLM 위키를 만들고, 각 에이전트들이 자기가 가지고 있는 대화 내역보다 최신화된 LLM 위키를 참고하도록 하면 좋을 것 같다는 생각을 했다.
적용 전에 LLM 위키에 대해 좀 더 조사가 필요할 것 같다. Best Practice를 찾아보고 내 프로젝트에 적용할 수 있는 방안을 고민해봐야겠다.

## 나에게 적용한다면

#### 💡 내 업무에서 스킬로 자동화할 수 있는 것 더 찾아보기

개발할 때에는 커밋, PR, 이슈 생성 등을 스킬로 자동화하고, 교육 과정에서는 슬랙 채널 요약이나 그 날 배우고 고민한 내용 요약을 스킬로 자동화했다. 이외에도 내가 하는 일 중 번거롭고 불편한 일이 있다면 어떻게 편하게 자동화해서 내 생산성을 끌어올릴 수 있을지 고민해보자.
