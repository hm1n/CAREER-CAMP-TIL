## 오늘 배운 내용

#### 📌 최악의 프롬프트를 개선해보기

내가 평소에 얼마나 프롬프트를 안 좋게 쓰는지 돌아볼 수 있었다. 가장 많이 쓰는 건 '내 장점이 뭐야' 였는데, 맥락도 지시사항도 없는 제일 별로인 프롬프트라 이걸 개선해봤다.
아직 마음에 쏙 드는 내 강점을 찾진 못했지만, 그래도 개선 전후로 응답의 퀄리티가 올라가는 걸 느낄 수 있었다. 앞으로 더욱 개선하고, 참고할 내용은 참고해서 이력서도 한 단계 개선할 수 있도록 노력해야겠다.

#### 📌 배포용 Skill을 만들고 검증 도구 추가하기

슬랙 채널의 인사이트를 요약하는 스킬을 만들고, Counter API 호출을 달아 검증 준비까지 완료했다. 내일 슬랙에 공유해보려고 하는데, 사용 횟수가 얼마나 집계될지 궁금하다. 그렇게 많은 횟수는 나오지 않겠지만 검증 도구를 찾아보고, ADR을 작성해보고 그 중 하나를 선택해서 직접 추가한 것 자체가 의미가 있는 것 같다. 앞으로 또 유용한 스킬들을 만들어보고 공유할 수 있도록 하자.

## 더 알아보고 싶은 것

#### ❓ 이력서 개선 방안을 좀 더 사람스럽게 작성하는 방법

아무리 프롬프트를 개선해도 AI가 제안하는 나의 장점이 공감이 가질 않는 이유는 문장이 AI스럽기 때문인 것 같다. 내가 출력된 내용을 보고 다시 작성할 수도 있지만, 그것도 번거롭고 귀찮으니 진짜 사람이 쓰는 것처럼 문장을 작성할 수 있도록 조련하는 방법은 없는지 찾아보고 싶다.

## 나에게 적용한다면

#### 💡 개선한 강점 프롬프트를 토대로 이력서 개선하기

강점 프롬프트 결과를 토대로 이력서를 개선해봐야 하는데 아무래도 추천 개선안과 문장이 너무 AI스럽다보니 이건 내가 읽고 사람의 말로 다시 옮겨 써야 할 것 같다. 내일부터 이력서/포트폴리오 스터디도 시작하니까 본격적으로 이력서 개선 작업 시작해보자.

#### 💡 Skill 배포하고 실제로 호출 횟수가 집계되는지 점검하기

오늘 공유할 준비가 완전히 끝났으니까 내일 오전에 바로 공유하고 사용 횟수 집계 여부를 확인해봐야겠다. 그렇게 큰 사용 횟수가 집계될 거라고 생각하진 않지만, 횟수를 직접 추적하는 것만으로도 재미있을 것 같다.
