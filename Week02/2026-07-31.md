# 2026-07-31

## 오늘 배운 내용

#### 📌 다양한 관점에서 프롬프트 작성하기

오늘은 프롬프트를 작성할 때 명확한 역할과 관점을 지시하고, 동일한 상황과 맥락에서 역할과 관점에 따라 어떻게 프롬프트 결과물이 달라지는지 실습해봤다. 그렇게 크게 다른가? 싶었는데 정말 다른 인사이트들이 출력되는 걸 보고 놀랐다.
관점과 기준을 명확하게 지시할수록 명확한 결과물이 나온다는 걸 느꼈고, 실제 이력서에 개선할 수 있는 사항들을 많이 얻어갈 수 있었다. 'AI의 답변은 내가 넣는 맥락에서 나오는 거니까 결국 내가 아는 것들을 한번 더 정리해주는 정도겠지' 라고 생각했던 나를 반성하게 됐다. AI는 쓰기 나름이라는 걸 다시 한번 느꼈다.

#### 📌 프롬프트 엔지니어링 개선점 찾기

팀 과제로 프롬프트를 구체화하는 과제를 하면서 다른 분들이 어떻게 프롬프트를 작성하는지 배울 수 있었다. 오늘 가장 크게 느꼈던 나의 프롬프트 작성 방법의 개선점은 아래 2가지였다.

1. 명확한 역할(엔지니어, 기획자, CX 전문가 등)을 제시한다.
2. Best Practice를 웹으로 검색하고 활용하도록 지시한다.

그동안은 명확한 역할을 주지 않고 먼저 내 상황을 설명한 뒤에 특정 포인트에 대해 더 깊게 이야기하는 방식으로 아이디에이션을 했는데, 명확한 역할을 줬을 때 확실히 답변이 달라지는 걸 보고 앞으로는 역할을 제시하는 게 좋겠다는 생각을 했다.
또, 내가 잘 모르는 분야(CX 대시보드, 코드 리뷰 등)에 대해서는 먼저 Best Practice를 찾도록 지시하고, 나도 그 정보를 확인하면서 모르는 분야에 대해 지식을 쌓은 뒤 프롬프트를 개선하는 게 훨씬 좋은 결과물을 얻을 수 있다는 것을 느꼈다. 모른다고 일단 박치기하지 말고 Best Case를 리서치해봐야겠다는 걸 상기하게 됐다.

## 더 알아보고 싶은 것

#### ❓ LLM 위키의 다양한 활용 방안 알아보기

사실 오늘 옵시디언을 LLM 위키로 잘 사용하고 계시는 다른 교육생 분께 질문드리고 싶은 내용이 많았는데, 바빠서 질문을 못 드렸다. 다음 주에는 꼭 질문드리려고 한다.

- 내가 이해한 활용 방법이 맞는지 확인
- 볼트 전체의 git 범위가 어떻게 되는지 구체적으로 질문
- 개인 생산성 향상을 위해 적용하고 있는 방식에 대해 질문
- 노션에서 옵시디언으로 전환하는 것에 대한 의견 질문
- 왜 옵시디언 볼트인지, 각 프로젝트마다 로컬로 저장하는 방법은 고려하지 않았는지 질문

#### ❓ 코드 리뷰 방법론에 대해 조사하기

코드 리뷰 프롬프트를 작성하면서 내가 코드 리뷰 방법에 대해 너무 모른다는 걸 느꼈다. 다른 기업의 코드 리뷰 방법에 대한 게시글을 참고하는 게 코드 리뷰 방법에 대한 지식을 늘리는 데 도움이 될 것 같다. 그리고 개인적으론 **코드 레벨에서의 고민이나 처리 방식을 개선한 경험**이 부족해서 이런 부분을 좀 더 채워나가야 할 것 같다.

#### 💡 오늘 정리한 프롬프트 원칙을 다음 프롬프트 작성 시 적용할 수 있도록 체크리스트 작성하기

- [ ] 내가 잘 모르겠을 땐 Best Practice를 참고하도록 지시하기

위 2가지를 앞으로 프롬프트에 꼭 반영하자.
